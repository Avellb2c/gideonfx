Ruta 1

Windows Server

Recomendado para un control plane administrado por el equipo de TI.

Server 2019/2022 · 64-bit
1

Prepara el servidor

Usa una cuenta local o de dominio con permisos de administrador, 8 GB de RAM, 4 vCPU y al menos 20 GB libres. Configura una IP estable y sincronización de hora.

tzutil /s "SA Pacific Standard Time"
w32tm /resync
2

Ejecuta OneClick

Extrae el paquete en una carpeta local, abre PowerShell como administrador y ejecuta el instalador. El modo fresh crea un entorno nuevo; usa clone sólo con un respaldo validado.

cd C:\Gideon\installers\WINDOWS
.\INSTALL_GIDEON_MASTER_WINDOWS.cmd -InstallMode fresh
3

Configura TLS y WebAdmin

Abre Acceso externo y TLS, registra el nombre DNS y carga un certificado válido. Mantén WebAdmin en HTTPS; Guacamole/guacd debe escuchar sólo en la red interna o loopback.

4

Protege la administración

Cambia la contraseña inicial, activa MFA, crea roles mínimos y valida el registro en Auditoría. Genera Agents desde Crear instalador para cada sede.

Ruta 2

Ubuntu Server

Ubuntu 22.04/24.04 LTS con systemd, Python 3.11+ y contenedores para Guacamole.

LTS · systemd
1

Prepara el sistema

Asigna IP/DNS estables, actualiza el reloj y usa un usuario con sudo. Abre únicamente HTTPS desde el exterior.

sudo timedatectl set-timezone America/Lima
sudo timedatectl set-ntp true
sudo apt update
2

Instala con el paquete

Desde la raíz del bundle, ejecuta el instalador Linux. Para un entorno completamente offline define GIDEON_ALLOW_ONLINE_INSTALL=0 y conserva el caché firmado junto al paquete.

cd ~/gideonfx
bash installers/LINUX/INSTALL_GIDEON_MASTER_LINUX.sh
3

Comprueba servicios

sudo systemctl status gideon-web-admin
sudo systemctl status gideon-agent-gateway
sudo docker compose -f payload/linux/app/deploy/guacamole/docker-compose.yml ps

Si un servicio aparece degradado, revisa Diagnóstico y salud antes de reiniciar producción.

Ruta 3

AWS · EC2

Arquitectura recomendada: una VPC, subred privada para el control plane y un único punto HTTPS.

EC2 · VPC · IAM

Orden recomendado

  1. Crea una VPC y subred privada; asigna un security group que permita sólo 443/TCP desde el proxy o balanceador.
  2. Usa una instancia Ubuntu LTS con rol IAM mínimo para SSM, métricas y backups. Evita guardar access keys en el servidor.
  3. Asocia un DNS como admin.example.com mediante Route 53 y termina TLS en el balanceador o en Gideon.
  4. Instala el bundle Ubuntu y configura el Gateway. Los Agents salen por túnel inverso mTLS; no abras 3389, 5900 ni el puerto de guacd a Internet.
  5. Activa snapshots cifrados de EBS y prueba una restauración antes de registrar sedes.
Regla de seguridad

El security group no debe permitir “0.0.0.0/0” en puertos de Agent. Para soporte usa SSM Session Manager o una VPN administrativa.

Ruta 4

Azure · VM

VM Ubuntu o Windows Server protegida por NSG, identidad administrada y DNS controlado.

VM · NSG · Managed Identity

Orden recomendado

  1. Crea una VNet y una subnet dedicada. En el NSG permite sólo 443/TCP desde el Application Gateway, VPN o rangos administrativos.
  2. Activa Managed Identity y Azure Monitor; no dejes client secrets en .env ni en imágenes de VM.
  3. Publica un nombre DNS estable y usa certificado válido. Si usas Application Gateway, conserva TLS hasta WebAdmin cuando la política lo requiera.
  4. Ejecuta el instalador Windows o Ubuntu según la VM. Valida servicios, auditoría y un Agent de prueba antes de incorporar más sedes.
  5. Configura Azure Backup para datos, certificados y configuración; documenta el procedimiento de recuperación.
Acceso administrativo

Prioriza Azure Bastion o Just-In-Time VM access. El túnel inverso de Agents evita abrir puertos públicos por sede.
